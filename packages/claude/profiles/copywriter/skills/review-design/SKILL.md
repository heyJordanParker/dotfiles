# Check the design

One Process: read the built design against the argument the plan and copy make, and find where the design betrays it. This pass owns the rendered piece — does the visual hierarchy carry the copy's hierarchy, does anything hide or fight the words. Rendered action visibility (is the CTA actually visible on screen) lives here, one skill, one owner; the copy-side CTA logic is cro-review's.

## 1. Hierarchy matches the argument

### Make the visual weight follow the copy's weight
Fail where the design's emphasis contradicts the argument — the promise small and a secondary point large, the reading order fighting the section order, the eye landing somewhere the copy did not lead it.

### Check the render against the section's wireframe intent
Read each section's layout block in the deliverable's Wireframe.md and fail where the built design departs from its stated intent — the wrong section shape, elements placed against the block, the structure the copy specified not carried. The copy owns where things go; this pass confirms the render honored it.

## 2. Nothing hides the copy

### Keep every load-bearing line and action visible
Fail a headline lost against its background, body set too small or too low-contrast to read, or a primary action pushed off-screen or camouflaged by the layout. The rendered CTA must actually be seen.

## 3. Nothing fights the copy

### Let imagery and motion serve the words, never compete
Fail decoration that pulls attention off the argument, an image that contradicts the claim beside it, or motion that distracts from the read.

Verification: the design read against the plan's argument section by section; every place the render hides, shrinks, or fights a load-bearing line or action named with what the copy intended.
