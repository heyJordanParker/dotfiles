# The wireframe format

The one home for how a page's Wireframe.md is written. Every page skill and every writer produces the wireframe against this format. Design works from Wireframe.md plus Design.md; review-design and cro-review read each section's layout block back and gate the render against it.

### The writer produces the wireframe after the copy converges
Wireframe.md is a production output, not a plan file. Once the page's copy is locally clean, the writer wireframes the finished copy — the writer is the sole author of the file. It carries the section order, the per-section rationale, a layout block per section, and the title chain. Nothing about visual styling: copy owns where things go and why, design owns how they look.

### Give every section a layout block
Each section names three things: its section shape (centered, two-column, cards, media-left, and the like), where each element sits within that shape, and its CRO notes — CTA button size and prominence, and above-fold rules such as when NOT to put a CTA above the fold. The block states intent and reason, never visual styling.
Evidence (owner, verbatim): "our copy docs need some sort of wireframing to where things go – what kind of sections (centered, two-columns, etc etc) and what kind of things to think about (e.g. font size on CTA buttons or NOT adding a CTA button above the fold)"

### Carry the title chain into the wireframe
The page's chosen title chain goes into Wireframe.md in order — the same chain the writer designed before any body and the skim layer check-structure reads.

### Put every visual-carried enumeration in its section's layout block
Enumerations of kinds, industries, or examples — and any content a visual carries better than prose (plans, worked figures, capability grids, pricing) — belong in the section's layout block as the named visual plus the copy strings on it, never a prose list. Plans and pricing are shown, never summarized in prose.

Template:
    Wireframe.md — OUTPUT · the writer · from the converged copy
    Title chain: <the selected chain, in order>
    Sections, in order:
      - <Section> — answers <Reader question / objection> — shape: <centered|two-column|cards|…> — elements: <placement> — CRO: <CTA size/prominence, above-fold rule>
